hcp

A Ruby client for the Housecall Pro API.

Open an account with a key, name a location where the key opens several, and read what the account answers: the business it belongs to, its jobs, its visits and its leads. It needs the standard library, three files of Active Support, and the company gem, whose words it answers in.

The Housecall Pro API, answered in the vocabulary of the company gem: a key opens an account, the account answers the business it belongs to, its leads, its jobs and its visits, and nothing else. Where a caller reads nothing, this gem has no method. Version 2.0.0 is the first to speak that vocabulary, and hcp is one adapter of it — every word here means what it means on any other platform the vocabulary is answered for.

How to install

# 
gem install hcp

Or, in a Gemfile, pinned to the current major:

gem 'hcp', '~> 2.0'

~> major.minor means bundle update never crosses a breaking change. The gem asks for Ruby 3.2 or later, for Active Support — three files of it, not the whole of it — and for the company gem, which it takes from RubyGems on its own.

The account, and the location

#

An account is a key, acting as one location where the key opens several. The key is the account's own, so a process serving several accounts holds several, and no thread reads another's:

account = Hcp::Account.new key: 'the-api-key'
account = Hcp::Account.new key: 'the-api-key', company_id: 'loc_1'

company_id: is sent as X-Company-Id. The account a key belongs to refuses the header, so it is only sent where a location is named. Every record read through the account is read as that location, so a job read as one reaches its lines as the same one.

The account answers four things, and each is documented on its own page: business, jobs, visits and leads.

The business

#

The business behind the key: the account, or the one location of a franchise it acts as. Hcp::Business.

business = account.business
business.id, business.name
business.phone        # => '5555550100', ten digits however Housecall Pro wrote them, or nil
business.subsidiaries # => the business itself first, then every location under it, flat

Housecall Pro answers a franchise as a tree several levels deep; subsidiaries reads it flat and is never empty, and each id in it is what company_id: takes. A single company is its own one subsidiary. Every reader a business has is on the records page.

Jobs, and visits

#

A list is narrowed to a window measured from now, and to nothing else. The jobs booked to start within one are walked a page at a time, each read flat and in dollars however Housecall Pro nested it or counted it:

account.jobs.past(4.weeks).each do |job|
  job.id, job.description, job.created_at, job.scheduled_at, job.completed_at
  job.notes             # => "- Gate code 1234\n- Dog in the yard", one to a line
  job.amount            # => 330.0, dollars as a BigDecimal, where Housecall Pro said 33000
  job.quote             # => an Hcp::Quote, the estimate option the job was created from, or nil
  job.location          # => an Hcp::Location, or nil where the job is booked nowhere
  job.location.customer # => an Hcp::Customer: id, name, surname, email, phone
  job.lines             # => Hcp::Line, read off the job's own line_items endpoint on first ask
end

Housecall Pro calls a visit an appointment and files it inside a job, so the visits booked to start within a window are read off the jobs booked across it, each saying what its job says and carrying it:

account.visits.upcoming(2.weeks).each do |visit|
  visit.id, visit.description, visit.starts_at, visit.ends_at, visit.anytime?
  visit.job              # => the Hcp::Job the stop belongs to, its location and customer along
end

Nothing is read until the walk starts, and a page only once the one before it runs out. past and upcoming take how far the window reaches from now — a duration in Rails, a number of seconds outside it, or nothing at all for as far as the account goes. Everything a job reads is on the jobs page, and everything a visit reads on the visits page.

Leads

#

Opening a lead opens its customer with it, and hands back what Housecall Pro filed both under:

lead = account.leads.create name: 'Ada', surname: 'Lovelace', phone: '5550000001',
  email: 'ada@example.com', description: 'Fix the sink', notes: 'Very interested in buying',
  address: { street: '1 Example Street', city: 'Springfield', state: 'CA', zip: '90210' },
  source: 'The Lead Generator'
lead.id, lead.customer.id

Moving a lead through the pipeline names the status as the account names it; a name the account has no status for raises Hcp::Error:

account.leads.find('lea_1').update status_name: 'Won'

These are the only two writes the gem has, and the leads page says where each word lands.

Errors

#

Everything descends from Hcp::Error, which descends from Company::Error, so one rescue still catches the lot. Hcp::Throttled, a Company::Throttled, is a refusal for rate, so one retry covers every platform:

begin
  account.jobs.past(4.weeks).each { |job| puts job.description }
rescue Company::Throttled
  # the same question, asked a little later, is answered
rescue Company::Error => error
  error.message # => what Housecall Pro said
end

Nothing here sleeps. A caller told to come back later has a queue that can bring the whole job back, which is worth more than a worker asleep holding a connection open. The errors page has every class and every message.

Events

#

Hcp::Event reads a webhook payload, and reaches the network for nothing. The signature and timestamp headers Housecall Pro signs one with are Hcp::Event::SIGNATURE_HEADER and Hcp::Event::TIMESTAMP_HEADER.

event = Hcp::Event.new params
event.lead_id, event.customer_id, event.conversion_type, event.conversion_id
event.job_id, event.estimate_id, event.scheduled_at, event.completed_at
event.invoice_id, event.invoice_job_id, event.invoice_amount

An event needs no key and no account: it is a reader over a hash. The events page says which reader each event carries.

Every resource

#

Three lists are read off the account. The rest are reached through one of them, and are handed back already read.

  • Jobs

    Work a Housecall Pro user accepted: what it is, who it is for, and what it comes to. Hcp::Job

  • Visits

    The stops a job is booked as, which Housecall Pro calls appointments. Hcp::Visit

  • Records

    The business, and what a job carries: its location, its customer, its lines and its quote.

  • Leads

    Opening a lead, and moving one through the pipeline. The only two writes the gem has. Hcp::Lead

  • Events

    Reading a webhook payload, without reaching the network for anything. Hcp::Event

  • Errors

    What is raised, when, and what it descends from. Hcp::Error

That is the whole of it. The install notes, the changelog and the test suite live upstream, and every method on every page carries a one-line description in the API reference.
