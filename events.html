Events

What Housecall Pro sent a webhook to say, read without reaching the network.

An event is a reader over the payload: it names what happened and hands back the IDs of what it happened to. There is no request in it, so it costs nothing and needs no key.

Reading a payload

#

Hcp::Event is handed the payload of a Housecall Pro webhook and reaches the network for nothing. It has no key, no company_id and no request in it — it is a reader over a hash.

event = Hcp::Event.new params
event.type # => :job_scheduled

type is what Housecall Pro named the event, with its dot turned into an underscore, so job.scheduled reads as :job_scheduled and fits a case the way a symbol should:

event = Hcp::Event.new params

case event.type
  when :job_scheduled then Hcp::Job.find event.job_id, company_id: company_id
  when :estimate_sent then Hcp::Estimate.find event.estimate_id, company_id: company_id
  when :invoice_sent then event.invoice_amount
end

The payload is read by symbol, so a hash parsed from JSON needs its names symbolized. In Rails, controller params already answer to both:

event = Hcp::Event.new JSON.parse(request.raw_post, symbolize_names: true)

An event read from nothing names nothing rather than raising: Hcp::Event.new.type.to_s is empty.

A job event

# 
event = Hcp::Event.new event: 'job.scheduled', job: { id: 'job_1',
  customer: { id: 'cus_1' }, original_estimate_id: 'csr_1',
  schedule: { scheduled_start: '2026-06-26T10:45:00Z' },
  work_timestamps: { completed_at: '2026-06-26T12:45:00Z' } }

event.type         # => :job_scheduled
event.job_id       # => 'job_1'
event.customer_id  # => 'cus_1'
event.estimate_id  # => 'csr_1'
event.scheduled_at # => 2026-06-26 10:45:00 UTC
event.completed_at # => 2026-06-26 12:45:00 UTC

estimate_id is the estimate the job was won with, where there was one. Reach for the whole record with Hcp::Job.find event.job_id — a webhook names what happened, and the API answers for what it happened to.

A lead event

#

A converted lead carries what it was last turned into, which is an estimate or a job:

event = Hcp::Event.new event: 'lead.converted', lead: { id: 'lea_1',
  customer: { id: 'cus_1' }, conversions: [ { 'type' => 'Estimate', 'id' => 'csr_1' } ] }

event.type            # => :lead_converted
event.lead_id         # => 'lea_1'
event.customer_id     # => 'cus_1'
event.conversion_type # => :estimate
event.conversion_id   # => 'csr_1'

Housecall Pro sends every conversion the lead has had. conversion_type and conversion_id read the last of them, which is the one the event is about.

An invoice event

# 
event = Hcp::Event.new event: 'invoice.sent',
  invoice: { id: 'inv_1', job_id: 'job_1', amount: '33000' }

event.invoice_id     # => 'inv_1'
event.invoice_job_id # => 'job_1'
event.invoice_amount # => 0.33e3, a BigDecimal — $330.00

Housecall Pro counts the invoice in cents and this gem reads it in dollars, the way it reads every other sum.

An estimate event

#

An estimate sent on its own, rather than through a job, names itself:

event = Hcp::Event.new event: 'estimate.sent', estimate: { id: 'csr_1' }

event.type        # => :estimate_sent
event.estimate_id # => 'csr_1'

The two headers

#

Housecall Pro signs a webhook and stamps it, and names both in headers. The gem holds the two names:

Hcp::Event::SIGNATURE_HEADER # => 'Api-Signature'
Hcp::Event::TIMESTAMP_HEADER # => 'Api-Timestamp'

It holds the names and checks neither. Verifying the signature is the caller's, and belongs where the request arrives rather than where the payload is read.
