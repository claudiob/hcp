Hcp::Estimate

Estimates

Work a Housecall Pro user offered to do, priced as one option or several.

An estimate is narrowed and booked the way a job is, and carries what the customer was actually offered: a list of options, each priced, each with its own status and its own notes.

An estimate is a job before there is a job. It reads the same six conditions, the same schedule and the same status words, and it adds the one thing a job has no need of: the options.

Reading estimates

#

Hcp::Estimate is read from the top, and answers the same eight entry points a job does.

Hcp::Estimate.all
Hcp::Estimate.find 'csr_2ac4e89ea3f94fba99145285fb7bbce5'
Hcp::Estimate.first
Hcp::Estimate.count  # => 811
Hcp::Estimate.limit 50
Hcp::Estimate.order updated_at: :desc
Hcp::Estimate.where work_status: :scheduled
Hcp::Estimate.includes :attachments

Housecall Pro files an estimate under an ID beginning csr_, which is also what job.original_estimate_id holds on a job that was won with one:

job = Hcp::Job.first
Hcp::Estimate.find job.original_estimate_id if job.original_estimate_id

Hcp::Estimate.where customer_id: 'cus_51eb63f50bda440292ec0bebc169eb0a'

Hcp::Estimate.where scheduled_at: ..2.days.ago

employee_ids, work_status and location_ids are the ones Housecall Pro takes more than one of — Hcp::Estimate::MANY — so a bare string works as well as a list of them.

#

An estimate's options need no expansion. They arrive inside the estimate Housecall Pro already answered with, priced and read.

What an estimate reads

# 
estimate = Hcp::Estimate.find 'csr_2ac4e89ea3f94fba99145285fb7bbce5'

estimate.id              # => 'csr_2ac4e89ea3f94fba99145285fb7bbce5'
estimate.estimate_number # => '51108564'
estimate.lead_source     # => 'HouseAccount', or nil
estimate.work_status     # => :scheduled
estimate.rated?          # => false
estimate.created_at      # => 2026-06-21 13:39:50 UTC
estimate.updated_at      # => 2026-06-21 13:39:50 UTC

An estimate is booked and stamped the way a job is, and reads the same schedule and the same four moments:

estimate.schedule.starts_at      # => 2026-06-23 17:15:00 UTC
estimate.schedule.ends_at        # => 2026-06-23 18:00:00 UTC
estimate.schedule.time_zone      # => 'America/Los_Angeles'
estimate.schedule.arrival_window # => 30, minutes

estimate.on_my_way_at # => when the pro said they were on their way, or nil
estimate.started_at   # => when the visit started, or nil
estimate.completed_at # => when the visit was finished, or nil

Where Housecall Pro files the estimate in its own workflow reads by the same table a job's status does — the seven words, and the five symbols they come back as.

estimate.customer.name  # => 'Ada'
estimate.customer.phone # => '5550000001'
estimate.address.city   # => 'Springfield'
estimate.address.type   # => :service
estimate.assigned_employees.map &:name # => ['Ada Example']

The options a customer was offered

#

An estimate is priced as one option or several, and every one of them arrives with the estimate. options is an array, not a relation: the records are already in hand, so there is nothing to walk and nothing to count with a second request.

estimate.options.count            # => 2
estimate.options.map &:total_amount # => [0.0, 0.145e4]

option = estimate.options.first
option.id               # => 'est_7e935e461264420eb5d6d5421558d9a3'
option.name             # => 'Option #1'
option.option_number    # => '51108564'
option.status           # => 'submitted for signoff'
option.approval_status  # => nil, until the customer answers
option.message_from_pro # => 'Thank you for doing business with us!'
option.total_amount     # => 0.145e4, a BigDecimal — $1,450.00
option.tags             # => ['Pipeline Automation']
option.notes.map &:content # => ['No phone (estimate $20-$50)']
option.created_at       # => 2026-06-21 13:39:50 UTC
option.updated_at       # => 2026-06-22 13:45:09 UTC

status and approval_status are read as Housecall Pro writes them, in its own words, because an option moves through a workflow of its own rather than through the one a job and an estimate share. Every reader an option has is on the records page.

What an estimate does not do

#

Housecall Pro takes no PUT, POST or DELETE this gem speaks for an estimate or for an option, so neither Hcp::Estimate nor Hcp::Estimate::Option has a create, an update or a destroy. Sending an estimate, approving an option and turning one into a job all happen in Housecall Pro, and reach this gem only as a webhook.

An estimate has no line items here either. What an option comes to reads off total_amount, and the line-by-line breakdown is a job's.
