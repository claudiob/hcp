Hcp::Lead

Leads

Somebody who asked a Housecall Pro user for work, before there is a job.

A lead is opened with a name, a number and an address, and moved through the account's own pipeline by the name of a status. These are the only two methods in the gem that write.

Everything else in this gem reads. A lead is opened, and a lead is moved — two writes, both here, and both through the same plumbing as a read, so a refusal is read the three ways Housecall Pro writes one.

Leads come off the account

#

A lead is filed for the location the account acts as, so it is reached the way everything else is: through the account the key opens.

account = Hcp::Account.new key: 'the-api-key', company_id: 'loc_1'
account.leads

The key is the account's own, so a process serving several accounts holds one account each and never has to say which key it means twice. Leads write as that same location: one account, one key, one X-Company-Id.

Opening a lead

#

Opening a lead opens its customer with it, and hands back what Housecall Pro filed both under:

lead = account.leads.create name: 'Ada', surname: 'Lovelace', phone: '5550000001',
  email: 'ada@example.com', description: 'Fix the sink', notes: 'Very interested in buying',
  address: { street: '1 Example Street', city: 'Springfield', state: 'CA', zip: '90210' },
  source: 'The Lead Generator'
lead.id, lead.customer.id

Eight words, the vocabulary's own, and every one of them named. What Housecall Pro calls each of them is not what a caller would:

What create takes
WordWhere it landsWhat it is
name:customer.first_namewhoever asked for the work
surname:customer.last_nametheir surname
phone:customer.mobile_numberthe number to reach them on
email:customer.emailthe address to answer them at
address:addressa hash: street, city, state, zip
description:note, the first line of itwhat the work is called
notes:note, under the descriptionwhat else was said about it
source:lead_source, on the lead and on the customerwhere the lead came from

A lead has no title of its own on Housecall Pro, so the description heads the note and the notes follow it, one line under the other. That is the vocabulary's answer to a platform with one field where it reads two.

Anything left blank is left out of the payload rather than sent as an empty string, so a lead with no email opens with no email rather than with one Housecall Pro would file as blank.

A lead reads its id and the customer Housecall Pro opened beside it, which it names by ID alone. It is the same customer a job's location hands back, read whole there:

lead.id          # => 'lea_9f0a1c8d2b4e4f0f8c1d2e3f4a5b6c7d'
lead.customer.id # => 'cus_c3fd9f15d014442aa3165fccf68ae95c'

A lead Housecall Pro will not open raises Hcp::Error, carrying what it said. A connection it will not take raises the same, so one rescue covers both.

Moving a lead through the pipeline

#

The pipeline is where a Housecall Pro user files a lead while they are still chasing it. A lead is named by its ID and moved to the status going by a name:

account.leads.find('lea_1').update status_name: 'Won'

find reaches the network for nothing: there is no endpoint that reads a lead back, so it names the lead and reads nothing until it is asked to move it. What a lead was turned into arrives instead as a webhook.

The name is the account's own word for the status, not a word this gem has a list of — an account that calls it 'Closed — sold' is asked for exactly that. The gem reads the account's statuses, finds the one going by the name, and refuses where there is none rather than moving the lead somewhere unintended:

account.leads.find('lea_1').update status_name: 'Nowhere'
# => Hcp::Error: Status Nowhere not found for lead lea_1

That is two requests: one to read the statuses, one to move the lead. A refusal from either raises Hcp::Error carrying what Housecall Pro said.

The only two writes

#

create and update are the only methods in this gem that change anything on a Housecall Pro account. Jobs, visits and every record under them read, and only read.

There is no destroy, and no list of leads: Housecall Pro answers a POST for one and a PUT for the pipeline, and nothing that reads one back. Where a caller reads nothing, this gem has no method.
