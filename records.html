How these are reached

#

Seven records, and not one of them is read from the top. None extends Queryable, none has a path of its own, and none answers all, where or find. Each is only ever handed back by a parent, which is why they share a page rather than each having one with four readers on it.

Two kinds of parent hand them over. Some arrive inside the answer Housecall Pro already sent, and cost nothing more to read. Others are a list Housecall Pro keeps under the parent, and are a relation of their own — one request, walked lazily, countable, and findable by ID.

Every one of them reads id, which is the ID Housecall Pro files the record under. None of them writes.

Addresses

#

Where a customer is billed, or where the work happens. Hcp::Address.

address = Hcp::Customer.first.addresses.first

address.id            # => 'adr_703532314fe64002a5104d3e0a29f611'
address.type          # => :billing, or :service
address.street        # => '1 Example Street'
address.street_line_2 # => 'Apt 4', or nil
address.city          # => 'Springfield'
address.state         # => 'CA'
address.zip           # => '90210'
address.country       # => 'US'
address.latitude      # => 34.0
address.longitude     # => -118.0

type is the one reader that is not read straight through: Housecall Pro writes it as a string and it comes back as :billing or :service. The coordinates are where Housecall Pro placed the address, and are nil where it placed it nowhere.

A job's address and a customer's address are the same class read two ways. The job carries one, already inside the answer; the customer's are a relation, and cost a request when they are walked.

Employees

#

A pro on a Housecall Pro account. Hcp::Employee.

employee = Hcp::Estimate.first.assigned_employees.first

employee.id         # => 'pro_738721e93c12463ea2e756267f5a5fe7'
employee.name       # => 'Ada Example'
employee.first_name # => 'Ada'
employee.last_name  # => 'Example'
employee.email      # => 'ada@example.com'
employee.phone      # => '5550000001'
employee.role       # => 'admin'
employee.created_at # => 2026-05-02 09:12:44 UTC
employee.updated_at # => 2026-06-19 17:03:11 UTC

name joins whichever of the two names Housecall Pro holds, the way a customer's does. There is no list of an account's employees here: Housecall Pro answers one endpoint for them and this gem reads none, so a pro is reached only through the job or the estimate they are assigned to.

An appointment names its pros by ID rather than handing back employees, because that is all Housecall Pro sends with a visit.

Schedules

#

When work is booked for, and how wide a window the customer was given. Hcp::Schedule.

schedule = Hcp::Job.first.schedule

schedule.starts_at      # => 2026-06-26 10:45:00 UTC
schedule.ends_at        # => 2026-06-26 12:45:00 UTC
schedule.time_zone      # => 'America/New_York'
schedule.arrival_window # => 30, minutes
schedule.appointments   # => the visits, where the list was asked for them

time_zone is an IANA zone, and is what a time is shown to a customer in — the moments themselves are UTC. appointments is empty unless the list that read the job asked for them with includes(:appointments): it holds none of them, rather than none at all. The visits have a page of their own.

A job that has never been booked has no schedule, and job.schedule is nil.

Line items

#

One line of what a job comes to. Hcp::LineItem.

item = Hcp::Job.first.line_items.first

item.id          # => 'rli_d193fee8eb734d13acad5d7e42691333'
item.name        # => 'Exterior trim - Fascia repair'
item.description # => 'Reattach or install a single piece of prebent fascia...'
item.quantity    # => 1.0
item.unit_price  # => 0.33e3, a BigDecimal — $330.00
item.unit_cost   # => 0.5e0, a BigDecimal — $0.50
item.amount      # => 0.33e3
item.kind        # => :labor

kind is :materials, :labor, or one of the gratuities and discounts, with the spaces Housecall Pro writes them with turned into underscores. The three sums are dollars, as BigDecimal, because Housecall Pro counts them in cents.

job.line_items.sum &:amount   # => 0.33e3
job.line_items.group_by &:kind

Notes

#

Something a pro wrote on a job or on an estimate option. Hcp::Note.

note = Hcp::Job.first.notes.first

note.id      # => 'nte_890617b1c1a24b228464e26c9beefdf4'
note.content # => 'Gate code is 4021'

Two readers, because Housecall Pro sends two things. Notes arrive inside the job or the option that carries them, so notes is an array and reading it costs nothing more.

Invoices

#

A bill raised for a job. Hcp::Job::Invoice.

invoice = Hcp::Job.first.invoices.first

invoice.id             # => 'inv_1a0e94c5d7b34f0aa2c1e6f8b9d0c3a4'
invoice.invoice_number # => '51575153'
invoice.status         # => 'paid'
invoice.amount         # => 0.33e3, a BigDecimal — $330.00
invoice.due_amount     # => 0.0
invoice.sent_at        # => 2026-06-26 13:02:11 UTC
invoice.paid_at        # => 2026-06-27 08:41:55 UTC

status is read as Housecall Pro writes it, in its own words, because an invoice moves through a workflow of its own rather than through the one a job and an estimate share. sent_at and paid_at are nil until each has happened.

Estimate options

#

One of the things a customer was offered on an estimate, priced on its own. Hcp::Estimate::Option.

option = Hcp::Estimate.first.options.first

option.id               # => 'est_7e935e461264420eb5d6d5421558d9a3'
option.name             # => 'Option #1'
option.option_number    # => '51108564'
option.status           # => 'submitted for signoff'
option.approval_status  # => nil, until the customer answers
option.message_from_pro # => 'Thank you for doing business with us!'
option.total_amount     # => 0.145e4, a BigDecimal — $1,450.00
option.tags             # => ['Pipeline Automation']
option.notes.map &:content # => ['No phone (estimate $20-$50)']
option.created_at       # => 2026-06-21 13:39:50 UTC
option.updated_at       # => 2026-06-22 13:45:09 UTC

An option carries its own notes and its own tags, so two options on one estimate can be annotated apart. The estimate page shows them in context.
