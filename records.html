How these are reached

#

Five records, and not one of them is read from the top. None has a list of its own, none takes a window, and none answers find. Each is only ever handed back by a parent, which is why they share a page rather than each having one with four readers on it.

Two kinds of parent hand them over. Some arrive inside the answer Housecall Pro already sent, and cost nothing more to read. Others live at an endpoint of their own, and are read once, on the first ask, and held afterwards.

Where each one comes from
RecordReached byWhat you get
Hcp::Businessaccount.businessone record, one request
Hcp::Locationjob.locationone record, already read
Hcp::Customerjob.location.customerone record, already read
Hcp::Linejob.linesan array, one request on the first ask
Hcp::Quotejob.quoteone record, its amount one request

Every one of them reads id, which is the ID Housecall Pro files the record under. None of them writes. A lead hands back a customer of its own, which is the same Hcp::Customer read from a lead rather than from a job.

The business

#

Who the account belongs to: the one business behind a key, as the location it acts as. Hcp::Business. There is no list of businesses and no ID to find one by — a key reads its own, and nothing else.

business = account.business

business.id           # => '6513270e-269e-4d37-b2a7-4de452e6b438'
business.name         # => 'Example Handyman Group HQ'
business.phone        # => '5555550100', or nil where no number can be dialed
business.subsidiaries.map &:name
# => ['Example Handyman Group HQ', 'Example Handyman Region', 'Handyman - Springfield']

phone is ten digits however Housecall Pro wrote them, punctuation and a leading 1 taken off, and nil where what it holds is not a number anybody could dial.

subsidiaries is never empty: it is the business itself, then every location under it at any depth, in the order Housecall Pro lists them. A single company is its own one subsidiary, and a franchise reads flat however deep Housecall Pro nests it. Each subsidiary's id is what company_id: takes:

account.business.subsidiaries.each do |location|
  Hcp::Account.new(key: key, company_id: location.id).jobs.past 4.weeks
end

Locations

#

Where the work happens: one address Housecall Pro books a job at. Hcp::Location.

location = job.location

location.id        # => 'adr_703532314fe64002a5104d3e0a29f611'
location.street    # => '1 Example Street'
location.city      # => 'Springfield'
location.zip       # => '90210'
location.latitude  # => 34.0
location.longitude # => -118.0
location.customer  # => whose place it is

Housecall Pro files the address and the customer side by side under the job; the vocabulary reads a location with whose place it is beside it, so the job hands back one record and the customer hangs off it. Both arrive inside the job Housecall Pro already answered with, so reading them costs nothing more.

The coordinates are where Housecall Pro placed the address, and are nil where it placed it nowhere. job.location is itself nil on a job booked nowhere.

Customers

#

Whoever the work is for. Hcp::Customer.

customer = job.location.customer

customer.id      # => 'cus_c3fd9f15d014442aa3165fccf68ae95c'
customer.name    # => 'Ada'
customer.surname # => 'Lovelace'
customer.email   # => 'ada@example.com'
customer.phone   # => '5550000001'

A customer's name is their first name, or the business's where a person has none — an account that works for companies reads a name either way, rather than a blank where a company should be.

phone is the first of the mobile, home and work numbers that can be dialed, as ten digits, and nil where none of the three can be. Housecall Pro holds all three; a caller wants the one to ring.

A lead hands back a customer too, which is the one Housecall Pro opened with it.

Lines

#

One line of what a job comes to: how many of a thing, what it is called, and what it comes to. Hcp::Line.

line = job.lines.first

line.id          # => 'rli_d193fee8eb734d13acad5d7e42691333'
line.name        # => 'Exterior trim - Fascia repair'
line.description # => 'Reattach or install a single piece of prebent fascia...'
line.quantity    # => 1, and 1.5 where half of one was billed
line.amount      # => 0.33e3, a BigDecimal — $330.00

Housecall Pro files a job's lines under their own endpoint rather than beside the job, so they are read once, on the first ask, and held afterwards. That is one request per job whose lines are read, and none for a job whose lines are not:

job.lines.sum &:amount # => 0.33e3, one request
job.lines.count        # => 1, and no second one

A whole quantity reads as an Integer — 3 Faucets rather than 3.0 Faucets — and a fraction keeps its point, since rounding it would lie about what was billed. amount is dollars, as a BigDecimal, because Housecall Pro counts in cents.

Quotes

#

A price a Housecall Pro user sent, which Housecall Pro calls an estimate option: a job names the option it was created from, and an estimate holds one option or several. Hcp::Quote.

quote = job.quote

quote.id     # => 'est_7e935e461264420eb5d6d5421558d9a3', named beside the job
quote.amount # => 0.145e4, a BigDecimal — $1,450.00

job.quote is nil where the job was won without one, and the ID costs nothing: Housecall Pro names it beside the job. The amount is the one thing it does not send. Housecall Pro reads an estimate by its own ID and not by an option's, so the option is found among the customer's estimates — one request, on the first ask, and nil where the option is not among them.

What was quoted and what the job came to are two numbers, and the gem keeps them apart: job.amount is what the work is billed at, and job.quote.amount is what the customer was offered before it.
