A customer is the record a job, an estimate and a lead all point at. It reads, and this release writes none of it.

Reading customers

#

Hcp::Customer is read from the top, and answers the same eight entry points every queryable resource does.

Hcp::Customer.all
Hcp::Customer.find 'cus_c3fd9f15d014442aa3165fccf68ae95c'
Hcp::Customer.first
Hcp::Customer.count  # => 5379
Hcp::Customer.limit 50
Hcp::Customer.order created_at: :desc
Hcp::Customer.where q: 'Ada'
Hcp::Customer.includes :do_not_service

With a location named:

company_id = '143e13ab-943d-483b-b9f9-14821c53c849'

Hcp::Customer.find 'cus_c3fd9f15d014442aa3165fccf68ae95c', company_id: company_id
Hcp::Customer.count company_id: company_id

Narrowing a list of customers

#

A customer is narrowed by one free-text search rather than by named fields. Housecall Pro reads q across the name, the email and the numbers it holds, so one string is the whole of the search.

Hcp::Customer::FILTERS
ConditionWhat Housecall Pro takesValue
qqone string
location_idslocation_idsone, or several
 
Hcp::Customer.where q: 'Ada'
Hcp::Customer.where q: 'ada@example.com'
Hcp::Customer.where q: '5550000001'
Hcp::Customer.where(q: 'Ada').order(created_at: :desc).limit 5

location_ids is the one condition Housecall Pro takes more than one of, so a single ID works as well as a list. That set is Hcp::Customer::MANY.

q takes a value and not a range, and says so rather than sending something Housecall Pro would read as a filter it does not have:

Hcp::Customer.where email: 'ada@example.com'
# => Hcp::Error: email is not one of: q, location_ids

Hcp::Customer.where(q: 'a'..'z').first
# => Hcp::Error: q takes one value, not a range

Ordering a list of customers

#

Two columns, and one order at a time.

Hcp::Customer::SORTS
In order ofDirection
created_at:asc or :desc
updated_at:asc or :desc
 
Hcp::Customer.order created_at: :desc
Hcp::Customer.order updated_at: :asc

Hcp::Customer.order name: :asc
# => Hcp::Error: name is not one of: created_at, updated_at

Bringing more back

#
Hcp::Customer::EXPANDS
ExpansionWhat it asks for
:attachmentswhat is filed against the customer
:do_not_servicewhether the account has marked them not to be served
 
Hcp::Customer.includes(:do_not_service).limit 20

This release reads neither back off Hcp::Customer: the expansion asks Housecall Pro for them, and no method hands them over yet. A customer's addresses need no expansion — they arrive with the record, and read as a relation of their own.

What a customer reads

# 
customer = Hcp::Customer.where(q: 'Ada').first

customer.id         # => 'cus_c3fd9f15d014442aa3165fccf68ae95c'
customer.name       # => 'Ada Example'
customer.first_name # => 'Ada'
customer.last_name  # => 'Example'
customer.email      # => 'ada@example.com'
customer.company    # => 'Example Bakery', where the customer is a business
customer.kind       # => :homeowner
customer.lead_source # => 'HouseAccount', or nil
customer.tags       # => ['VIP']
customer.notifications_enabled? # => true
customer.created_at # => 2026-06-21 14:01:07 UTC
customer.updated_at # => 2026-06-21 14:01:07 UTC

name is whichever of the two names Housecall Pro holds, joined, and never a stray space where it holds one of them. A business reads off company, which is a field of its own rather than a third name.

Housecall Pro holds three numbers — mobile, home and work — and a caller almost always wants whichever one there is. phone is the first of the three the customer can be reached on:

customer.phone # => '5550000001'

Where a customer is billed and served

#

Addresses are a relation under the customer, so they walk, count and find by ID:

customer.addresses.count # => 1

address = customer.addresses.first
address.id        # => 'adr_703532314fe64002a5104d3e0a29f611'
address.type      # => :billing, or :service
address.street    # => '1 Example Street'
address.city      # => 'Springfield'
address.state     # => 'CA'
address.zip       # => '90210'
address.latitude  # => 34.0
address.longitude # => -118.0

Every reader an address has is on the records page. Housecall Pro takes no conditions on a customer's addresses, so the relation walks and counts but does not where.

What a customer does not do

#

Housecall Pro takes no write for a customer that this gem speaks yet, so Hcp::Customer has no create, no update and no destroy. Opening a customer alongside a lead is the one way the gem puts one on the account.
