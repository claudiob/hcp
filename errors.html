A refusal is Housecall Pro's to send, and the gem's only job is to hand it over in words a caller can act on: one class for everything, one for the refusal that is worth retrying, and both named in the vocabulary rather than in this platform's.

Two classes, one rescue

#

Everything this gem raises descends from Hcp::Error, which descends from Company::Error, so one rescue still catches the lot — including anything a later release adds.

What the gem raises
ClassDescends fromRaised where
Hcp::ErrorCompany::ErrorHousecall Pro would not answer
Hcp::ThrottledCompany::ThrottledHousecall Pro refused the request for rate
 
begin
  account.jobs.past(4.weeks).each { |job| puts job.description }
rescue Hcp::Throttled
  # the same question, asked a little later, is answered
rescue Hcp::Error => error
  error.message # => what Housecall Pro said
end

Company::Throttled is itself a Company::Error, so the order matters: the narrow one first, and the wide one after it, the way any two rescues are written.

Housecall Pro writes a refusal three ways — the message under an error, the message as the error, and the message on its own. All three read as error.message. A connection Housecall Pro will not take is turned into the same class as a request it will not answer, so a caller has one thing to rescue rather than two.

Rescued as a platform, or as any platform

#

Both classes have a parent in the company gem, which is the point of them. Code that speaks to Housecall Pro alone rescues Hcp::Error. Code that speaks to whatever platform an account happens to be on rescues Company::Error, and the retry it writes for a refusal for rate is written once:

begin
  account.jobs.past(4.weeks).each { |job| record job }
rescue Company::Throttled
  retry_later
rescue Company::Error => error
  report error.message
end

hcp is one adapter of that vocabulary. A refusal for rate means the same thing here as it does anywhere else it is answered, which is why it is a Company::Throttled rather than an error of this gem's own.

Rate limits

#

Hcp::Throttled is what Housecall Pro answering 429 becomes. It is a refusal for rate and nothing else: the same question, asked a little later, is answered.

begin
  account.visits.upcoming(2.weeks).each { |visit| dispatch visit }
rescue Hcp::Throttled => error
  error.message # => what Housecall Pro said
end

Nothing here sleeps. A caller told to come back later has a queue that can bring the whole job back, which is worth more than a worker asleep holding a connection open. Reschedule on whatever your queue's backoff would have chosen.

On the two writes

#

Leads go out through the same plumbing the reads do, so they raise the same classes for the same reasons, and one more of the gem's own: a status the account has no word for. Rather than move the lead somewhere unintended, the gem refuses by name:

begin
  account.leads.find('lea_1').update status_name: 'Won'
rescue Hcp::Error => error
  error.message
  # => 'Status Won not found for lead lea_1'
end

That is the one message this gem writes itself. Every other one is Housecall Pro's, handed over as it was written.

What is not an error

#

A record Housecall Pro holds nothing for is not a refusal. A field it never answered reads as nil, a list it never answered reads as [], and neither raises:

job.completed_at # => nil, on a job that is not finished
job.location     # => nil, on a job booked nowhere
job.quote        # => nil, on a job won without one
job.lines        # => [], where Housecall Pro has none filed
account.jobs.past(4.weeks).first # => nil, where nothing was booked in the window

There is no Hcp::NotFound any more, because nothing here is read by an ID a caller supplies: a job comes round in a window and a lead is named rather than looked up. Where Housecall Pro answers 404 anyway, that is an Hcp::Error like any other refusal it sends.
